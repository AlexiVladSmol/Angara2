# Angara — этапы разработки

Статус: **PROPOSED**. Сроки не назначены. Каждый этап разбивается на небольшие Issues после уточнения его контрактов. Завершение этапа — принятое ревью и воспроизводимые результаты на конкретном SHA, а не отчёт модели «всё готово».

## Первый выпуск v0.1

| Этап | Зависимость | Результат | Основная приёмка |
| --- | --- | --- | --- |
| M00 — решения | Нет | Согласованные продукт, язык, границы, роли и целевая среда | Владелец явно подтверждает решения; docs/DECISIONS.md обновлён |
| M01 — каркас | M00 | Crate, CLI, TOML, check, toolchain, lockfile и базовый CI | Чистая сборка; check не открывает сеть; ошибочный config отклонён |
| M02 — назначение и политика | M01 | Канонизация URI/authority, source gate, ACL, контролируемый DNS и dial | Табличные и негативные тесты; запрещённый endpoint не получает соединения |
| M03 — HTTP | M02 | Потоковый HTTP/1.1 proxy на локальном стенде | GET/HEAD/POST, chunked, keep-alive, заголовки, 100-continue, обрывы |
| M04 — CONNECT | M03 | Двусторонние TCP-туннели | TLS через туннель; IPv6; ранние байты; EOF, таймауты, отсутствие ложного 200 |
| M05 — пользователи | M04 | Basic, локальные хэши, user ACL и лимиты auth | 407, неправильный пароль, keep-alive identity, отсутствие утечек и auth перегрузка |
| M06 — TLS до proxy | M05 | HTTPS-listener, сертификат, документированная доверенная CA для стенда | TLS-клиент подключается; неверное имя/доверие отклоняет клиент; plain auth вне loopback требует явного исключения |
| M07 — эксплуатация | M06 | Reload разрешённых настроек, graceful shutdown, итоговые лимиты, журналы и метрики | Некорректный reload не меняет состояние; SIGTERM ограничен; slow client и перегрузка не вызывают безграничный рост |
| M08 — кандидат v0.1 | M07 | systemd, инструкции, артефакт Linux, регрессии, профиль нагрузки и отчёт | Установка на чистой целевой ОС; release проверки и ручная проверка владельца |

M02 реализует лимиты, необходимые DNS/connect; M03 и M04 — необходимые пределы сетевых путей; M05 — лимиты auth. M07 объединяет их эксплуатационные настройки и проверяет весь жизненный цикл. Защита ресурсов добавляется вместе с соответствующей функцией.

До M05/M06 сервер используется только на изолированном локальном стенде. Публичный запуск промежуточных версий не является критерием разработки.

## Позднейшие этапы, порядок уточняется по потребности

| Этап | Содержание | Условие запуска |
| --- | --- | --- |
| M09 — parent proxy / v0.2 | HTTP/TLS до родителя, отдельные credentials, маршрутизация, loop protection | Отдельное утверждение требований и архитектурного решения |
| M10 — HTTP cache / v0.3 | Сначала ограниченный RAM cache, затем отдельное решение о диске | Утверждённая политика RFC 9111, изоляция и тесты корректности |

После v0.1 также можно выбрать иные задачи: bandwidth limits, квоты трафика, дополнительные auth backend, ARM64, пакеты для конкретных дистрибутивов. Они получают собственные решения и задания; не добавляются в реализацию случайно.

## Порядок выдачи заданий

1. Codex уточняет контракты ближайшего этапа, исходя из уже принятого кода.
2. Создаёт Issue с границами, criteria и тестовыми сценариями; перечисляет зависимости и документы.
3. DeepSeek предлагает короткий план, реализует код и тесты, открывает PR.
4. CI проверяет коммит; DeepSeek прикладывает SHA и результаты, включая непрошедшие/пропущенные проверки.
5. Codex проводит ревью; DeepSeek исправляет замечания.
6. Владелец принимает изменение или поручает слияние. Codex обновляет ход разработки и готовит следующее задание.

Детальный план всех будущих файлов не замораживается заранее. Новые сведения о HTTP-клиентах, нагрузке и ограничениях дистрибутива должны корректировать следующие задания через явные решения.

## Критерий готовности v0.1

- Все F01–F10 и N01–N07 имеют проверку либо согласованное документированное исключение.
- Обязательные проверки текущего релизного SHA проходят; неподтверждённые пропуски закрыты.
- Нет открытых блокирующих замечаний по protocol framing, ACL, credentials, resource exhaustion и утечкам.
- Проверены установка, конфигурация, TLS, авторизация, журналирование, остановка и обновление на целевой системе.
- Зафиксированы поддерживаемые протоколы, известные ограничения и результаты нагрузки; заявлений о более высокой скорости, чем Squid, без измерений нет.
- Владелец согласовал выпуск и сценарий первого развёртывания.
