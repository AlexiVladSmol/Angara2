### P2. В основном boot job осталась одна настоящая попытка `debootstrap`

Шаг `Boot pristine rootfs after debootstrap retry` — теперь единственная реальная загрузка через `debootstrap` в CI. Он запускает `boot.sh` с `M08_DEBOOTSTRAP_ATTEMPTS=2`. Подменённый `debootstrap` всегда проваливает первую попытку. Значит, на настоящую загрузку пакетов остаётся одна попытка — как на `main` до этого PR. Сетевой сбой при скачивании пакета, из-за которого открыт Issue #8, по-прежнему валит job.

Ожидаемое исправление в этом шаге:
- `M08_DEBOOTSTRAP_ATTEMPTS=4`: одна подменённая попытка плюс три настоящие, как по умолчанию;
- проверку `[ "$(sudo cat "$STATE")" = "2" ]` заменить на `-ge 2`: при сетевом сбое настоящих попыток может быть больше;
- в `grep` ожидать `debootstrap attempt 1/4 failed with exit code 1`.

Достаточно PR-прогона: `src/` не меняется, dispatch по D57 для этого не нужен.

### P3 (не блокируют)

- **Комментарий в `boot.sh` противоречит данным.** Там сказано, что `debootstrap` создаёт целевой каталог с umask вызывающего. Но head `3414e75` без предварительного `mkdir` был зелёным при `umask 077`. Значит, `debootstrap` сам создаёт каталог с 0755, а 0700 давал именно `mkdir -p` в скрипте. Сама правка (`install -d -m 0755`) верна, нужно поправить только объяснение.
- **Причина подтверждена только с одной стороны.** Красные прогоны 25 и 32–36 — с `mkdir` под `umask 077`, зелёные — без него или с 0755. Это согласуется с гипотезой, но запуска, где 700 приводит к падению, нет. Ставить его не нужно, просто не стоит писать «подтверждена» сильнее, чем есть.

### Итог

CHANGES_REQUESTED на `4b2ed3a`, причина — только P2. После правки и зелёного PR-прогона одобрю без повторного dispatch.
