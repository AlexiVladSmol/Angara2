# Angara — описание продукта

Требования утверждены владельцем в M00. Редакция 0.9 от 16 ноября 2026 года. M00–M07 приняты и слиты. M08 готов к реализации. [M08-r1](tasks/M08_RELEASE_CANDIDATE.md) · [Issue #23](https://github.com/AlexeiSmol/Angara/issues/23)

## Назначение

Angara — самостоятельный прямой web proxy для Linux. Клиент явно настраивает адрес прокси. Сервер проверяет доступ и передаёт HTTP-запрос либо создаёт CONNECT-туннель. Ориентир по классу задач — Squid: проксирование, пользователи, ACL, наблюдаемость и дальнейшее кэширование.

Первый стенд — Ubuntu Server 24.04 x86_64 с 10–20 устройствами. В перспективе поддерживаются все три сценария: личный сервер, организация и множество внешних пользователей. Начальный пилот проверяет общий прокси-сервис; расширения для больших установок принимаются по измерениям. Устройство может создавать несколько HTTP-соединений и CONNECT-туннелей: 20 устройств не означает лимит в 20 соединений.

## Границы первого выпуска

- Поддержка HTTP/1.1 на входе прокси и на исходящей HTTP-стороне. HTTP/2 сайта может проходить внутри непрозрачного CONNECT-туннеля.
- Для HTTPS-ресурсов клиент использует CONNECT. Поддержка absolute-form https URI отдельно не обещается в v0.1.
- Передача тела и туннеля потоковая: память не растёт пропорционально размеру загрузки.
- Локальное хранение хэшей паролей; работа с системными учётными записями, LDAP и Kerberos — отдельные расширения.
- Установка без обязательного Docker. Изолированные контейнеры допускаются для тестового стенда, если доступны в CI.
- В проекте будет собственный понятный формат конфигурации. Импорт squid.conf рассматривается позже как отдельный инструмент.
- Порт прокси по умолчанию — 3128; адрес первого запуска — loopback. Публичное прослушивание задаётся администратором явно.
- Источник истины — репозиторий, его Issues, PR и согласованные документы.

В v0.1 не включаются: SSL bump / перехват TLS сайтов, прозрачный proxy, reverse proxy, SOCKS5, UDP/QUIC proxy, ICAP/eCAP, GUI, кластер, внешняя БД и произвольные плагины.

## Следующие выпуски

**v0.2, обязательный этап M09:** parent proxy с HTTP или TLS-транспортом до родителя, отдельной авторизацией и правилами маршрутизации. Дополнительные методы входа по ключу рассматриваются по реальным требованиям клиентов: нестандартный секрет не делает обычный proxy совместимым с MTProto.

**v0.3, обязательный этап M10:** ограниченный shared HTTP cache с отдельным согласованием политики. Кэширование содержимого HTTPS внутри CONNECT без расшифровки невозможно; кэшируется только явно поддержанный HTTP-трафик.

**M11, обязательное будущее развитие:** современный TUI для статуса, соединений, пользователей, ACL и применения конфигурации через общий слой управления. Конкретная TUI-библиотека выбирается при выдаче задания.

**M12, возможное расширение:** локальная web-панель через тот же API, ориентир адреса 127.0.0.1:7029. Порт предварительный, интерфейс по умолчанию выключен. Web-панель не является условием готовности v0.1.

Не заявляются заранее превосходство над Squid и конкретная пропускная способность. Первые измерения фиксируют оборудование, версии, конфигурацию, число соединений, размер объектов и прогрев. Численные цели утверждаются по результатам базового стенда и требуемой нагрузки.

## Выбор стека

Согласовано: Rust + Tokio + hyper + rustls. Причины: контроль памяти и владения ресурсами, асинхронный сетевой ввод-вывод, зрелые реализации HTTP/TLS, удобная сборка одного сервиса. Цена выбора — более сложное сопровождение асинхронных типов и потоковых тел; эту сложность ограничиваем одним crate и небольшими этапами.

Точные версии совместимых библиотек и toolchain выбираются в M01 по актуальной официальной документации и фиксируются в репозитории. Один процесс использует несколько рабочих потоков; это не ограничение одним CPU-ядром.

## Уточнения по мере разработки

CPU/RAM и каналы первого стенда, число соединений на устройство, численные цели производительности, следующие дистрибутивы и ARM64 уточняются перед соответствующими испытаниями. Лицензия пока отложена; LICENSE без решения владельца не добавляется. Для M08 параметры испытательной среды фиксируются в отчёте. Лицензию и переход к публичному выпуску определяет владелец.
